Named Pipes (FIFO) and POSIX Signals
1. Client-Server using Named Pipes (FIFO)
Aim
To create a client-server application using Named Pipes (FIFOs) where the client sends messages and the server processes and responds to them.

Important Functions
mkfifo() – Creates a named pipe.
open() – Opens the FIFO.
read() – Reads messages from the FIFO.
write() – Sends messages through the FIFO.
close() – Closes the FIFO.
unlink() – Removes the FIFO.
Multiple Clients
When multiple clients communicate with one server, their messages may be handled one after another depending on the server design. Synchronization is important to avoid message conflicts and ensure correct communication.

2. POSIX Signal Handling
Aim
To create a program that handles SIGINT, SIGTERM, and SIGUSR1 and demonstrates asynchronous event handling.

Important Functions
signal() / sigaction() – Registers a signal handler.
SIGINT – Generated by Ctrl+C.
SIGTERM – Requests process termination.
SIGUSR1 – User-defined signal.
kill() – Sends a signal to a process.
Signal Flow
External Event
      ↓
    Signal
      ↓
Signal Handler
      ↓
Handle the Event
Signal Handler
A signal handler is a function that is automatically called when a specific signal is received.

Signals are asynchronous, meaning they can occur at any time while the program is running.

Easy Memory
mkfifo()  → Create FIFO
open()    → Open FIFO
read()    → Receive
write()   → Send
signal()  → Handle signal
SIGINT    → Ctrl+C
SIGTERM   → Termination
SIGUSR1   → User-defined signal
Conclusion
Named pipes provide communication between independent processes, while POSIX signals allow a process to respond asynchronously to events.
